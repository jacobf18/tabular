Two-Sided Chunked Compression for Matrix Completion

Cross-only variant: compressed context flows along row and column axes.

Motivation

TabImpute currently scales to large matrices via chunked imputation: the matrix is partitioned into chunks, each chunk is imputed independently, and results are reassembled. This works mechanically but degrades predictive quality, because each chunk loses access to information that lives in other chunks.

A missing entry in one part of the matrix may be best predicted using factor information identified by entries elsewhere; chunked inference severs that signal. We propose a chunked compression scheme that respects the row/column symmetry of matrix completion and integrates with TabImpute via end-to-end joint training. Cross-chunk context flows along the matrix's row and column axes — the directions that classical matrix completion methods rely on.

Architecture

The matrix is partitioned along both axes into a grid of chunks. For any chunk designated as the target — the chunk containing the entry currently being predicted — the rest of the matrix decomposes into source categories defined by axis alignment with the target.

  • Column-aligned chunks share the target's columns. They are compressed into Krow latent rows per chunk, summarizing how the target's columns behave outside the target chunk.
  • Row-aligned chunks share the target's rows. They are compressed into Kcol latent columns per chunk, summarizing how the target's rows behave outside the target chunk.

These compressed regions are stitched onto the target chunk to form an extended virtual matrix, which is what the predictor (TabImpute) operates on. The extended matrix has the target chunk at full resolution with compressed extensions along its row and column axes — preserving the spatial structure of the original matrix.

Why row–column symmetry matters

Matrix completion's information flow is two-directional in a way that supervised tabular prediction is not. Predicting an entry M[i,j] requires information about row i (what other columns in row i look like) and information about column j (what other rows in column j look like). A single set of compressed slots that mixes the two loses the structure — the predictor would have to disentangle factor sources from a flat summary.

By separating compression into row-summaries (from column-aligned chunks) and column-summaries (from row-aligned chunks), the architecture preserves the directional structure of the imputation problem. Compressed rows extend the target vertically; compressed columns extend it horizontally. The predictor receives context in exactly the shape it would consume real context, just at compressed cardinality.

Training procedure

The compressor and TabImpute are trained jointly, end-to-end. For each training step:

  1. Sample a synthetic matrix from the TabImpute prior (cheap, given our DGP).
  2. Partition it into a grid of chunks (chunk shape and grid shape randomized across steps).
  3. Designate one chunk as the target; apply masking to entries within the target.
  4. Run the compressor on every cross-aligned chunk to produce its compressed output: Krow latent rows if the chunk is column-aligned with the target; Kcol latent columns if row-aligned.
  5. Stitch the compressed regions onto the target chunk in their spatially appropriate positions, forming the extended virtual matrix.
  6. Run TabImpute on the extended matrix; compute imputation loss on the masked entries of the target chunk.
  7. Backpropagate through both modules.

To ensure all chunks contribute gradient signal, we either rotate the target chunk across steps or compute loss on multiple chunks per step. Importantly, the training regime exactly matches the deployment regime: the model is trained on chunked-and-stitched inputs from the start, eliminating the train–test mismatch that arises when chunking is applied only at inference.

Compute considerations

Unlike approaches whose pretraining is bottlenecked by expensive synthetic data generation, the TabImpute DGP is essentially free relative to model forward and backward cost. Three implications follow.

  • Diversity. We can sample matrices with arbitrarily varied rank, size, sparsity, and factor structure at no per-sample cost.
  • Realistic training scale. We can train directly on multi-chunk matrices at deployment scale, rather than extrapolating from small examples.
  • Curriculum. Chunk count, chunk size, and matrix rank can be ramped over training without throughput concerns.

Initialization regimes

Three initialization regimes are worth comparing for the joint training.

  • From scratch. Both modules randomly initialized; cleanest scientifically but requires a full pretraining run.
  • Warm-started predictor. Predictor initialized from existing TabImpute weights; compressor randomly initialized; both jointly fine-tuned. Recommended starting point given existing TabImpute investment.
  • Frozen predictor. TabImpute weights frozen; only the compressor trained. Cheapest option; serves as a clean test of how much TabImpute's representation space already accommodates compressed context.

TabImpute's representations are shaped by a generative imputation objective and must encode the joint distribution over all columns to support arbitrary masking patterns. This makes its representation space considerably more general than that of supervised tabular foundation models, and we expect a compressor trained against a frozen TabImpute predictor to align more easily than against a frozen supervised predictor.

Open design questions

Compressor module sharing. A single compressor that conditions on a compression-mode flag (row vs. column) and produces the appropriate output shape is the most parameter-efficient option. Separate modules give more capacity. Worth ablating.

Mask-awareness in the compressor. The compressor should likely see each chunk's mask channel, since the reliability of compressed factor estimates depends on which entries were observed. Easiest implementation: the mask is an additional input channel.

Aggregation across many source chunks. When the target chunk has multiple column-aligned chunks providing compressed rows, those summaries can be either concatenated (linear context growth) or further aggregated (truly fixed context). Concatenation is simpler and likely sufficient for moderate chunk counts.

Row–column asymmetry for asymmetric domains. For symmetric matrix completion (rec sys, sensor data), shared compressor logic is natural. For asymmetric domains like EHR data — where rows are exchangeable patients and columns are non-exchangeable features — row-summaries and column-summaries may want different inductive biases. Particularly relevant for the PRISM use case.

The cross-only variant is the minimal architecture that respects row–column symmetry while remaining tractable to train and deploy. It deliberately omits off-axis information; whether this loses meaningful signal in practice is an empirical question and the natural extension is a corner-block channel.
